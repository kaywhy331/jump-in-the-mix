## September 8 recovery-state evidence checkpoint

- Added `db:export-recovery-state` and `db:review-recovery-state` for the missing source-evidence step in recovery. Capture uses one read-only PostgreSQL snapshot, discovers every ordinary table, hashes complete rows and primary identities inside PostgreSQL, and exports only the selected account/access/recipient/send restrictions needed by typed reconciliation. Hashing identities preserves large numeric and composite keys without copying arbitrary future primary-key values. Included index columns do not change identity. Known contact notes, message bodies, passwords, MFA material and access-token values are omitted. The artifact still contains selected account/recipient identifiers and is treated as personal data.
- Recovery state uses authenticated encryption with a key derived specifically for this purpose from the backup key. Reading rejects tampering, wrong-purpose encryption, wrong keys, symlinks, oversized input, duplicate identities and incomplete formats. Capture refuses held sources, filtered row-security results, missing read privileges, unsupported inheritance/partition/foreign tables and missing primary keys. Cursor reads and artifact/row/time limits bound the operation. Existing outputs are never overwritten; normal/error/interruption paths clean temporary plaintext. Forced process/host termination still requires inspecting that operation's private artifacts.
- The review requires a verified target hold, matching authenticated backup/source identity, a state at least as recent as the backup and matching table/column/key shape. It counts missing/changed records and changed safety fields without exposing row identifiers or values. It binds the observation to the hold/archive, state digest and target digest. It remains explicitly read-only and reports no permission to reopen, even when counts match. A capture point does not establish continuity or cover changes made afterward.
