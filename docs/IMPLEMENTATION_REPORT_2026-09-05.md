## Flexible workflows

- Owners can rename, order, add, and retire stages. The initial journey is Lead → Prospect → Client → Retention, with direct entry to Client for a confirmed sale and Retention for completed work.
- Recorded milestones, elapsed days, and completion of the plan assigned by a stage can cause transitions. Each transition has an explanation in the contact timeline. Owners can move a person manually and pause the journey globally or for one person.
- A stage can start a chosen plan. Moving stages preserves independent assignments, manual stops, and contact permissions. Existing contacts remain unassigned until explicitly classified; plan changes apply to future entries.
- Calendar meetings and time blocks support contact links, timezone and daylight-saving validation, conflict checks, deliberate overlaps, editing, cancellation, private subscriptions, and downloads.
- Lead connections offer hosted forms and authenticated JSON intake, with recipes for website forms, email, messaging, calls, social platforms, CRMs, and scanning devices. Existing CSV, vCard, and device-contact import remains available.
- Intake retries are idempotent. Matching uses exact normalized contact methods or a connection-scoped external ID; conflicts and archived matches wait for review. Incoming data does not overwrite existing contact details or permissions.

## Compatibility and remaining hosting limitation

iCalendar enables import, export, and subscription with Google, Outlook, Apple, and other compatible providers, subject to their sharing options and refresh timing. It does not provide native OAuth or real-time two-way editing. Generic intake requires the source provider, an automation service, or a backend to map events; selecting a source type does not connect an account automatically. The setup guide specifies supported payloads, limits, retry behavior, and private-site authentication.

**The test hosting's worker timer is not qualified for reliable timing.** Netlify registers the minute schedule but has not shown recurring execution, including after the trigger was recreated. The existing GitHub fallback does execute automatically: a scheduled run at September 6, 01:03 UTC produced the matching 01:03:25 UTC heartbeat. However, observed gaps between scheduled runs exceeded 90 minutes despite a five-minute cron. Heartbeat health can pass briefly after a fallback run and become stale again; it is not proof of sustained scheduling.

At the final database observation, 01:22:31 UTC, the latest heartbeat was still 01:03:25 UTC. No manual invocation was used after either final deployment to make the check pass.

Event-driven journey rules execute when their milestone is recorded. Elapsed-time rules, completed-plan maintenance, feed refreshes, and scheduled deliveries depend on the worker and may run late on this test site. A reliable hosted timer or the documented standalone worker must be qualified before relying on delivery times. The health threshold was not increased to conceal this issue.

No award, comprehensive accessibility certification, or universal provider compatibility is claimed. Physical devices, non-Chromium browsers, native provider account connections, and visual craft were not qualified in this work.

## Push ownership continuation

Push opt-in previously outlived the browser session, so the old account could keep sending to a shared browser after sign-out or an account change. A subscription is now bound to the session that enabled it. The sender excludes expired and unbound subscriptions and rechecks the exact binding before provider handoff. Session deletion clears the binding while retaining subscription delivery receipts. Creating a new session replaces the browser's previous session atomically; same-account renewal transfers its opt-in, while a different account must explicitly turn reminders on.

Device controls carry the account scope under which they were opened. The API derives identity from the authenticated session and rejects mismatched scopes, missing authentication and view-only support sessions with uncached JSON responses. An opt-in locks and rechecks its session before saving, so a revoked session cannot bind a device. Turning reminders off removes the server subscription; the browser endpoint can remain available for a later explicit opt-in. A delayed control from an old account cannot unsubscribe the next account's browser endpoint.

Push payloads include their account scope and subscription identifier. Before displaying application notification text, the service worker checks that the current session owns that subscription and reminders are still enabled. Missing legacy identifiers, a different account, sign-out, disabled reminders and an unavailable verification endpoint suppress that text. Account checks also close existing application notifications from other scopes. Browser-generated fallback notifications, the final handoff to the OS and actual device behavior still require physical qualification; the application cannot retract a notification already delivered outside its control.

The additive migration `20260906060000_push_session_ownership` leaves legacy subscriptions unbound because no browser session can be inferred safely. Those devices require fresh opt-in. An encrypted hosted backup preceded the migration. Deployment explicitly targeted the authorized private test site and preserved the separate production site's link.

## Complete Today navigation continuation

Today now reads bounded batches of 30, prioritizes open work in the database, and counts the complete filtered view. Counts describe follow-ups, since one person can have several.

First, Previous and Next navigation preserve the date, status and channel filters. Ordering positions contain the open/completed group, scheduled time and stable ID; they never supply workspace authority. Authenticated workspace boundaries remain ANDed into every query. Navigation can cross the open/history boundary, survive a deleted anchor, and return to the first surviving records when an old page disappears. Completed and skipped history remain chronological together. Changing a filter returns to the first matching batch. Snooze and stop-plan actions preserve the filtered navigation position.

Paging and Today filter changes detect actual unsent message edits, including those in closed sheets. The owner can keep editing, which reopens and focuses the draft, or discard the current view’s edits and continue. Successful navigation closes the old panels and focuses the Today heading. Modified/new-tab links retain native browser behavior. Preparation status is read before the list so a just-completed generation cannot report ready alongside an earlier list snapshot.
